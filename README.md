# VibeME Call — инструкция по запуску (для новичков)

Простой пошаговый гид, чтобы запустить приватные P2P-звонки локально, а затем развернуть на прод. Всё без регистрации и без хранения данных.

## Что потребуется
- Node.js 20+
- npm (устанавливается вместе с Node.js)
- Браузер Chrome/Firefox/Safari (последние версии) с доступом к микрофону

## Быстрый старт локально

1) Склонируйте проект и перейдите в папку:
```
git clone <URL_репозитория> VibeCall
cd VibeCall
```

2) Запустите бэкенд (сигнальный сервер):
```
cd backend
npm install
npm run dev
```
По умолчанию сервер слушает `http://localhost:3001`. В `.env` можно настроить `ALLOWED_ORIGINS` и `ENFORCE_HTTPS` (пример в `backend/env.example`).

3) В другом терминале запустите фронтенд:
```
cd ../frontend
npm install
npm run dev
```
Откройте в браузере `http://localhost:5173`.

4) Проверьте звонок:
- Нажмите «Create Room» — получите код комнаты и сразу зайдёте внутрь.
- Откройте новую вкладку/другой браузер, нажмите «Join Room» и введите код.
- Разрешите доступ к микрофону в обоих окнах. Звук идёт P2P, сервер передаёт только сигнализацию.

## Переменные окружения
- Фронтенд (`frontend/.env`): `VITE_SIGNALING_URL` (URL бэкенда), опционально TURN `VITE_TURN_URL`, `VITE_TURN_USERNAME`, `VITE_TURN_PASSWORD`.
- Бэкенд (`backend/.env`): `PORT`, `ALLOWED_ORIGINS` (через запятую), `ENFORCE_HTTPS=true/false`.

## Сборка для продакшена
- Фронтенд: `cd frontend && npm run build` → результат в `dist/` (для Cloudflare Pages).
- Бэкенд: `cd backend && npm run build` → `dist/server.js` (порт 3001). Есть `Procfile` и `Dockerfile` для Render/Railway/Fly.

## Развёртывание
- Бэкенд на Render/Railway/Fly: Node 20, команда запуска `npm run start`, переменные `ALLOWED_ORIGINS=https://<ваш-frontend>`, `ENFORCE_HTTPS=true`.
- Фронтенд на Cloudflare Pages: укажите `Build command: npm run build`, `Build output: dist`, и задайте `VITE_SIGNALING_URL=https://<ваш-бэкенд>`.

## Частые ошибки и решения
- **Микрофон не работает / нет звука**: проверьте разрешения в браузере; перезайдите, нажав «Allow». Убедитесь, что микрофон не выключен кнопкой Mute.
- **Комната не найдена**: код комнаты введён с ошибкой или сервер перезагружен. Создайте новую комнату и поделитесь новым кодом.
- **Room full**: достигнут лимит 4 участников. Создайте другую комнату.
- **Signaling unreachable / не подключается**: проверьте, что бэкенд запущен на `PORT=3001` и `VITE_SIGNALING_URL` указывает на него; убедитесь, что брандмауэр не блокирует порт.
- **HTTPS редирект мешает локально**: убедитесь, что `ENFORCE_HTTPS=false` в `.env` бэкенда и открывайте `http://localhost:5173`.
- **Проблемы со звуком в динамике (speaker toggle)**: не все устройства поддерживают `setSinkId`. Это ожидаемо; переключение может быть недоступно.
- **ICE/TURN ошибки**: по умолчанию используется STUN Google. Если сеть жёстко ограничена, добавьте свой TURN в переменные окружения фронтенда.

## Полезно знать
- Никаких баз данных и логов — всё в памяти, комнаты удаляются через 5 минут после выхода последнего участника.
- Медиа идёт только P2P, сервер видит только сигнализацию WebRTC.
- Маршруты: `/` и `/home` — выбор/создание комнаты, `/room/:code` — сама комната.
